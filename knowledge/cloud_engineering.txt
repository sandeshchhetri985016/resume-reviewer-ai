# Cloud Engineering Resume Evaluation Guidance
# Use this to evaluate and provide feedback on cloud engineering resumes.

## Key Resume Strengths to Look For
- Cloud certifications (AWS, Azure, GCP) with specific role/certification level
- Infrastructure-as-Code experience (Terraform, CloudFormation, Pulumi)
- Cost optimization metrics (e.g., "Reduced cloud spend by 40% through reserved instances")
- Migration projects (e.g., "Migrated 50 microservices from on-prem to AWS EKS")
- Incident response and SLO/SLA achievement rates
- Multi-cloud or hybrid cloud experience

## Metrics That Impress Cloud Leads
- Infrastructure uptime/reliability percentages (e.g., "99.99% uptime over 12 months")
- Cost savings achieved through architecture changes
- Number of services/infrastructure components managed
- Deployment frequency improvements (e.g., "Reduced deploy time from 2hrs to 15min")
- Incident response times (MTTR improvements)
- Scaling metrics (e.g., "Scaled system from 1K to 100K requests/second")

## Key Areas to Evaluate
### Cloud Platforms
- AWS: EC2, S3, Lambda, EKS/ECS, RDS, VPC, IAM, CloudFront
- Azure: VMs, Functions, AKS, Cosmos DB, AD, DevOps
- GCP: Compute Engine, Cloud Run, GKE, Cloud Storage, BigQuery

### Infrastructure & DevOps
- Terraform, Terragrunt, CloudFormation, Pulumi, Ansible
- Docker, Kubernetes, Helm, Istio, Linkerd
- CI/CD: GitHub Actions, GitLab CI, Jenkins, ArgoCD
- Monitoring: Prometheus, Grafana, Datadog, CloudWatch

### Reliability & Security
- High availability and disaster recovery design
- IAM policies, security groups, network ACLs
- Encryption at rest and in transit
- Compliance (SOC2, HIPAA, PCI-DSS in cloud context)

## Common Resume Mistakes
- Listing cloud services without context of use
- No mention of cost management or FinOps
- Missing incident response experience on call
- No IaC examples or tools mentioned
