# Software Engineering Resume Evaluation Guidance
# Use this to evaluate and provide feedback on software engineering resumes.

## Key Resume Strengths to Look For
- Open source contributions with GitHub links and stars
- Quantified impact (e.g., "Reduced API latency by 60%", "Improved test coverage from 45% to 92%")
- System design experience: architecture decisions, trade-off reasoning
- Production experience: deployments, on-call, incident response
- Full SDLC involvement from requirements to monitoring
- Multiple programming languages demonstrated with depth

## Metrics That Impress Engineering Managers
- Performance improvements (latency, throughput, memory usage)
- Test coverage percentages and quality metrics
- Number of production deployments per week/month
- Team size led or mentored
- Code review velocity (e.g., "Reviewed 200+ PRs annually")
- Bug reduction or incident response times
- Feature adoption or user impact metrics

## Critical Areas to Evaluate
### Technical Stack Fit
- Languages: Does the resume show depth in the languages the job requires?
- Frameworks: React vs Angular, Django vs Flask — match to job description
- Infrastructure: Cloud (AWS/GCP/Azure), containers (Docker/K8s), CI/CD
- Databases: SQL vs NoSQL, ORM usage, query optimization experience

### System Design
- Microservices vs monolith experience
- API design (REST, GraphQL, gRPC)
- Message queues, caching strategies, event-driven architecture
- Scalability considerations (horizontal scaling, sharding, CDN)

### Engineering Practices
- Testing strategy (unit, integration, E2E, TDD/BDD)
- CI/CD pipelines owned or improved
- Code review quality and mentoring
- Agile/Scrum ceremonies participation
- Technical documentation habits

## Common Resume Mistakes in Software Engineering
- Listing technologies without showing depth or context of use
- Missing GitHub, portfolio, or live demo links
- No quantified impact — just listing job duties
- Buzzword stuffing (listing 30+ technologies without actual proficiency)
- Not mentioning code review, mentoring, or team collaboration
- Omitting production experience (deployments, monitoring, incident response)
- Vague descriptions like "worked on" or "was involved in"
- No personal projects or side work (for early-career candidates)

## Resume Structure Recommendations
1. Technical Summary (years experience, primary stack, key achievements)
2. Technical Skills (categorized: Languages, Frameworks, Cloud, Tools)
3. Professional Experience (with specific tech stack and quantified impact per role)
4. Open Source / Side Projects (links to GitHub, description, stars/forks)
5. Education (degree, relevant coursework if early career)
6. Certifications (AWS, Azure, GCP, Kubernetes, Scrum Master)
7. Additional: Conference talks, blog posts, patents, technical writing

## Red Flags to Watch For
- Claims of expertise in too many languages (likely surface-level)
- No links to code or portfolio for mid/senior roles
- Resume doesn't mention the tech stack from job description
- No evidence of working on production systems
- Gaps unexplained if >6 months
- Career stagnation (same role title for 5+ years without growth)
